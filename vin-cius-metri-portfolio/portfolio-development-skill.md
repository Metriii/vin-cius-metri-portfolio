# 13. Arquitetura do projeto

O projeto deve separar claramente:

**Dados** → **Componentes** → **Apresentação**

A informação do portfólio não deve ficar espalhada pelos componentes.

## Estrutura recomendada

```text
src/
├── components/
│   ├── Navbar
│   ├── ProjectCard
│   ├── TechnologyCard
│   ├── CertificationCard
│   └── TimelineItem
├── sections/
│   ├── Hero
│   ├── About
│   ├── Technologies
│   ├── Projects
│   ├── Journey
│   ├── Certifications
│   └── Contact
├── data/
│   └── portfolio.ts
├── types/
│   └── portfolio.ts
├── assets/
└── styles/
```

A estrutura pode ser adaptada à tecnologia utilizada, mas o princípio de separação deve ser mantido.

# 29. Processo de trabalho do agente

Sempre que receber uma solicitação relacionada ao portfólio, o agente deve seguir este processo.

## Etapa 1 — Entender a solicitação

Identificar se a alteração envolve:

- conteúdo
- design
- projeto
- tecnologia
- responsividade
- performance
- SEO
- arquitetura

## Etapa 2 — Analisar impacto

Antes de modificar arquivos, identificar:

- componentes afetados
- dados afetados
- possíveis impactos no layout
- impactos no mobile
- possíveis links quebrados

## Etapa 3 — Priorizar dados centralizados

Sempre que possível, modificar:

```text
src/data/portfolio.ts
```

em vez de alterar múltiplos componentes.

## Etapa 4 — Implementar

Seguir:

- código limpo
- componentes reutilizáveis
- tipagem adequada
- separação de responsabilidades

## Etapa 5 — Validar

Após alterações, verificar:

- Desktop
- Mobile
- Links
- Responsividade
- Conteúdo
- Dados reais
- Ausência de informações inventadas
- Erros visuais
